# Нутри — сайт, Telegram Mini App и сервер ИИ

ИИ-нутрициолог для видеоблога о загородной кухне. Человек сканирует QR в выпуске, попадает в чат и получает свою версию блюда: порцию, нутриенты, специи и подачу по самочувствию.

```
index.html               лендинг с чатом            → https://k1b35.github.io/nutri/
app/index.html           Telegram Mini App (чат)    → https://k1b35.github.io/nutri/app/
photos/                  фото для лендинга (см. photos/README.md)
backend/index.py         облачная функция: принимает чат, зовёт модель, возвращает ответ
backend/system_prompt.md правила для ИИ — утверждает врач
backend/recipes.json     рецепты выпусков — заполняет команда, утверждает врач
backend/dev_server.py    локальный запуск функции для проверки
```

Схема: сайт / Mini App → Yandex Cloud Functions → Yandex AI Studio (DeepSeek V4.1 Flash или Qwen3.6 35B). Расчёты делает модель по правилам из `system_prompt.md`; ключ к модели хранится только в функции, в браузер он не попадает.

---

## Шаг 1. Yandex Cloud: аккаунт и каталог (10 минут)

1. Зайдите на console.yandex.cloud, создайте платёжный аккаунт (новым пользователям дают стартовый грант).
2. Откройте облако → каталог `default` (или создайте `nutri`). Скопируйте **идентификатор каталога** (Folder ID, начинается с `b1g…`).
3. Сразу настройте бюджет: Billing → Бюджеты → например 1000 ₽ в месяц с уведомлением на почту.

## Шаг 2. Доступ к модели (5 минут)

1. Identity and Access Management → Сервисные аккаунты → **Создать**. Имя `nutri-ai`, роль `ai.languageModels.user`.
2. Откройте `nutri-ai` → **Создать новый ключ → Создать API-ключ**. Область действия: `yc.ai.languageModels.execute` (если в списке есть `yc.ai.foundationModels.execute` — отметьте и её).
3. Сохраните **секретный ключ** — он показывается один раз. Никому его не пересылайте и не кладите в код сайта.

## Шаг 3. Облачная функция (15 минут)

1. Cloud Functions → **Создать функцию**, имя `nutri-chat`.
2. Создать версию в редакторе: среда **Python 3.12**, способ — «Редактор кода».
   Создайте три файла и вставьте содержимое из папки `backend/`: `index.py`, `system_prompt.md`, `recipes.json`.
3. Параметры версии:
   - Точка входа: `index.handler`
   - Таймаут: `30` секунд, память: `128 МБ`
   - Переменные окружения:
     - `YANDEX_API_KEY` = секретный ключ из шага 2 (надёжнее — через секрет Lockbox, кнопка «Добавить секрет»)
     - `FOLDER_ID` = идентификатор каталога из шага 1
     - `MODEL` = `deepseek-v4.1-flash` (дешевле и быстрее: `qwen3.6-35b-a3b`)
     - `ALLOWED_ORIGINS` = `https://k1b35.github.io`
4. **Создать версию**. На странице «Обзор» включите **Публичная функция**.
5. Скопируйте ссылку вида `https://functions.yandexcloud.net/d4e…` и откройте её в браузере. Должно показаться `{"ok": true, ...}`.
6. Вкладка «Тестирование», тело запроса:
   `{"httpMethod":"POST","body":"{\"messages\":[{\"role\":\"user\",\"text\":\"Мне 30, 60 кг, мёрзну\"}]}"}` — в ответе должен быть текст от модели.

## Шаг 4. Подключить чат к функции (2 минуты)

Вставьте ссылку функции:
- в `index.html` → `CONFIG.AI_ENDPOINT`
- в `app/index.html` → `const AI_ENDPOINT`

Сохраните и закоммитьте — GitHub Pages обновит сайт за минуту.

## Шаг 5. Telegram Mini App (10 минут)

1. В @BotFather: `/newbot` → имя и username бота.
2. `/newapp` → выберите бота → название, описание, картинка 640×360 → **Web App URL**: `https://k1b35.github.io/nutri/app/` → короткое имя, например `app`.
3. Ссылка на Mini App: `https://t.me/<username_бота>/app`. Вставьте её в `index.html` → `CONFIG.TELEGRAM_URL`.

## Шаг 6. QR-коды и метрики

- QR на сайт: `https://k1b35.github.io/nutri/?utm_source=qr&utm_content=ep1`
- QR в Telegram: `https://t.me/<username_бота>/app?startapp=ep1`

`ep1` — ключ выпуска: тот же, что в `recipes.json`. По нему ИИ понимает, о каком блюде речь, а в логах видно, из какого выпуска пришёл человек.

Метрики пилота:
- **QR → онбординг**: визиты с `utm_source=qr` → доля, отправивших первое сообщение (событие `chat_message`).
- **D7 retention**: в логах функции у каждого сообщения есть анонимный `anon`; доля тех, кто написал снова через 7+ дней.

Яндекс Метрика (по желанию): создайте счётчик на metrika.yandex.ru, номер вставьте в `CONFIG.METRIKA_ID`. В разделе «Цели» добавьте JavaScript-события `chat_message`, `cta_click`, `voice_start`.

Логи функции: Cloud Functions → `nutri-chat` → Логи. Тексты сообщений не пишутся — только метка выпуска, число сообщений, токены и время ответа.

## Шаг 7. Работа врача

- Проверить и утвердить `backend/system_prompt.md`: стоп-правила, нормы калорий и белка, формулировки аюрведы.
- Заполнить `backend/recipes.json`: для каждого выпуска — название и рецепт с КБЖУ, затем поставить `"draft": false`. Черновики ИИ не видит.
- После правок обновить файлы в функции (новая версия) — изменения применятся сразу.

## Сколько стоит

- Cloud Functions: каждый месяц бесплатно 1 млн вызовов и 10 ГБ×час — для пилота это 0 ₽.
- Модель (цены AI Studio с НДС за 1000 токенов): DeepSeek V4.1 Flash — 0,3 ₽ вход / 0,5 ₽ выход; Qwen3.6 35B — 0,2 / 0,3 ₽.
  Одно сообщение ≈ 3000 токенов на входе (правила + история) и 300 на выходе ≈ **1 ₽** на DeepSeek, **0,7 ₽** на Qwen. Рецепты в `recipes.json` увеличивают вход — держите их короткими.
- Защита от перерасхода: не больше 40 сообщений в сутки на человека (`DAILY_LIMIT`), не больше 700 токенов в ответе (`MAX_TOKENS`), бюджет с уведомлением в Billing.

## Локальная проверка (для программиста)

```bash
export YANDEX_API_KEY=... FOLDER_ID=...
python3 backend/dev_server.py          # http://127.0.0.1:8080
python3 -m http.server 8000            # сайт: http://127.0.0.1:8000
```
Временно поставьте `AI_ENDPOINT: "http://127.0.0.1:8080"` и `ALLOWED_ORIGINS=*`.

## Перед публичным запуском

- Политика обработки персональных данных (152-ФЗ) и ссылка на неё в футере: переписка о здоровье уходит на сервер.
- Проверить, что «Правила утверждает врач» и «Проверено врачом» на сайте — правда.
- Заменить заглушки: фото, имя и цитату врача, названия выпусков.
